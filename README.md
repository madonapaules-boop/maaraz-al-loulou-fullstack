# معرض اللؤلؤه | Full-Stack Storefront

هذا المستودع يضم نسخة محلية كاملة لتطبيق متجر عربي. يتكون من واجهة بـ **React + TypeScript + Vite**، وBack-end مستقل بـ **ASP.NET Core .NET 10 + EF Core**. لا يحتاج المشروع إلى استضافة أو دومين أو قاعدة SQL Server لكي تجرّبي الفكرة محلياً في البداية؛ سيبدأ الـAPI بقاعدة بيانات مؤقتة داخل الذاكرة مع بيانات تجريبية، ثم يمكن ربطه بـ SQL Server لاحقاً عند الحاجة.

## هيكل المشروع

| المجلد                     | الوظيفة                                                                   |
| -------------------------- | ------------------------------------------------------------------------- |
| `client/`                  | واجهة المتجر العربية: الكتالوج، البحث، المفضلة، السلة، الشحن والتواصل.    |
| `backend/`                 | ASP.NET Core API، لوحة الإدارة، Models، EF Core migrations، وSwagger.     |
| `backend/wwwroot/admin/`   | لوحة الإدارة المحلية، وتشمل إضافة وتعديل وحذف المنتجات والأقسام والطلبات. |
| `backend/Data/Migrations/` | أول migration لقاعدة SQL Server عند الانتقال لقاعدة دائمة.                |

## التشغيل على جهازك

ستحتاجين إلى **Node.js 20 أو أحدث** و**.NET SDK 10**. افتحي نافذتين Terminal داخل مجلد المشروع.

### النافذة الأولى: تشغيل الـ Back-end

```bash
cd backend
dotnet restore
dotnet run
```

سيعمل الـAPI محلياً على `http://localhost:5048`. افتحي هذه الروابط عند التجربة:

| الرابط                          | الاستخدام                                               |
| ------------------------------- | ------------------------------------------------------- |
| `http://localhost:5048/admin`   | لوحة الإدارة: المنتجات، الأقسام، المخزون وطلبات واتساب. |
| `http://localhost:5048/swagger` | اختبار كل API endpoints من المتصفح.                     |

بيانات المدير المحلية للتجربة هي `admin` وكلمة المرور `ChangeMeBeforeProduction!`. غيري كلمة المرور قبل أي نشر مستقبلي.

### النافذة الثانية: تشغيل الـ Front-end

```bash
pnpm install
pnpm dev
```

ثم افتحي رابط Vite الذي سيظهر في Terminal، وغالباً يكون `http://localhost:3000`. أثناء التطوير فقط، يقوم Vite تلقائياً بتحويل طلبات `/api` و`/uploads` إلى الـAPI المحلي على المنفذ `5048`؛ لذلك سيظهر الكتالوج الحقيقي من الـBack-end ولن تحتاجي إلى استضافة أو متغيرات بيئة حالياً.

## تجربة الربط

ابدئي بتشغيل النافذتين. بعد ذلك افتحي لوحة الإدارة وأضيفي منتجاً أو عدّلي المخزون أو فعّلي عرضاً. حدّثي صفحة المتجر أو انتقلي للكتالوج وستظهر البيانات القادمة من الـAPI، بما فيها: العروض، الأكثر مبيعاً، وصل حديثاً، الأقسام، الأسعار المخفضة، والمخزون المتاح.

## عند الانتقال إلى SQL Server

ليس مطلوباً الآن. عندما تحتاجين قاعدة دائمة، ضعي connection string آمنة في إعدادات جهازك ثم شغلي:

```bash
cd backend
dotnet ef database update
```

التفاصيل موجودة أيضاً في `backend/README.md`.

## قبل رفعه على GitHub

يمكنك رفع هذا المجلد كله كمستودع واحد. تم تجاهل build outputs و`node_modules` و`backend/bin` و`backend/obj` وملفات البيئة المحلية. بعد الرفع، اكتبي في وصف المشروع أنه يوفّر واجهة متجر عربية مرتبطة بـ ASP.NET Core API ولوحة إدارة محمية بـ JWT، مع جاهزية للانتقال إلى SQL Server والاستضافة لاحقاً.

> لا ترفعي أبداً كلمة مرور مدير حقيقية، أو connection string حقيقية، أو JWT key حقيقي إلى GitHub.

ملف `backend/appsettings.json` يحتوي فقط على قيم تطوير عامة لتشغيل المشروع محلياً. عند الانتقال إلى قاعدة بيانات حقيقية أو استضافة، ضعي القيم الفعلية في `appsettings.Local.json` أو متغيرات البيئة؛ كلاهما خارج الرفع إلى GitHub.
